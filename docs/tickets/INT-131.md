# INT-131 — durable reminder idempotency

Problem: an administrator cannot know whether a reminder was accepted when the provider commits and the HTTP response is then lost, times out, or returns an error.

Business impact: retrying with a new identity can send duplicates, while refusing to retry can leave an overdue reviewer unnotified.

Acceptance criteria: one stable logical request per assignment and UTC day; one provider receipt per key under concurrent calls; exact replay for an unchanged payload; conflict for a reused key with a different payload; persistence across process restarts; bounded validation; and an audit trail for requests, retries, and outcomes.

Technical approach: SQL Server owns the logical reminder and generates the stable key. The loopback provider stores a SHA-256 payload fingerprint and receipt in a durable SQLite database using an immediate transaction. The admin page always retries the same SQL-owned payload, then records the observed provider result without treating transport failure as proof that nothing committed.

Risks: a timeout is deliberately ambiguous, so callers must preserve both key and payload. SQLite serializes writers; the 5-second busy timeout bounds contention while the unique key remains the final invariant. Test-only post-commit failures require an explicit process setting and are unavailable during a normal launch.

Test evidence: `database/tests/int-131-reminders.sql`, `tests/Triage.NotificationApi.Tests/ReminderReceiptStoreTests.cs`, and `scripts/Test-Int131.ps1` cover 20-way contention at both storage boundaries, malformed and conflicting calls, post-commit 503 and timeout recovery, restart persistence, and two real Classic ASP retries.

Deployment notes: migration 005 consolidates any pre-existing duplicate logical requests before adding a unique index and installs the request/result procedures. The SQLite receipt file is local runtime state under `.local/` and is never tracked. Application rollback retains both durable stores and their stronger uniqueness invariants.
